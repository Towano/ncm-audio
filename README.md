# ncm-audio

`ncm-audio` 用于解密网易云音乐 `.ncm` 音频文件。它默认保留原格式，也可转码为 FLAC、M4A、MP4 或 MP3，并能写入歌曲信息和封面。启用 `-l` 后，可选择使用源文件旁的同名 LRC，或根据歌曲 ID 联网获取歌词。

## 快速开始

在仓库根目录选择一种方式构建程序。

### 脚本构建

```sh
sh ./setup.sh
./ncm-audio 歌曲.ncm
```

脚本会在项目根目录生成 `ncm-audio`。

### Cargo 构建

```sh
cargo build --release
./target/release/ncm-audio 歌曲.ncm
```

Cargo 会将程序生成在 `target/release/ncm-audio`，不会生成根目录的 `ncm-audio`。这种方式要求本机已安装 Rustup 和 Cargo。

两种方式默认保留原音频格式，并将结果写入当前目录的 `output/`。首次构建需要联网下载工具链或依赖。

## 主要功能

### 音频处理

- 解密 NCM 文件并读取音频格式、歌曲信息和封面。
- 默认保留原始音频格式；也可转码为 FLAC、M4A、MP4 或 MP3。
- 为输出音频写入标题、专辑、艺术家、音轨号及 JPEG/PNG 封面（格式支持时）。

### 歌词处理

启用 `-l` 后，可选择使用源文件旁的同名 LRC，或根据歌曲 ID 联网获取歌词。

### 输入类型

支持处理单个 NCM 文件、扫描目录或递归批量处理。

## 常用场景

命令行参数按以下顺序填写：

```sh
ncm-audio [-r] [-l] [-f] [格式] [输入文件或目录] [输出目录或文件]
```

省略格式时保留原始音频格式；省略输入时扫描当前工作目录；省略输出时写入当前工作目录的 `output/`。输入、输出的相对路径均以运行命令时的当前工作目录为准，与二进制位置无关。

解密单首歌曲并处理歌词：

```sh
./ncm-audio -l 歌曲.ncm
```

省略 `-l` 时只解密音频。启用歌词也会处理音频；已有音频时可选择保留音频并继续处理歌词。

递归处理目录并转换为 MP3，写入指定目录：

```sh
./ncm-audio -r mp3 音乐目录 converted
```

`-r` 找到几首歌都逐首处理；即使只找到一首，已有输出文件时也使用相同的选择规则。未启用 `-l` 时，`n` 和 Esc 都保留已有音频并跳过当前项；多首时继续下一首。

若要指定输出文件名，可对单首歌曲运行 `./ncm-audio m4a-aac 歌曲.ncm converted/新名字.m4a`。

查看完整命令行帮助：

```sh
./ncm-audio -h
```

也可以直接运行 `./target/release/ncm-audio`，或将任一编译出的二进制移到别处运行，输入和输出路径规则不变。

## 参数与格式

### 输出格式

| 类型 | 格式 | 说明 |
| --- | --- | --- |
| 保留原格式 | `original` | 默认格式，保留 NCM 中识别到的音频格式。 |
| 无损格式 | `flac` | 转为 FLAC；输入已经是 FLAC 时不转码。 |
| 有损格式 | `mp3` | 转为 MP3；输入已经是 MP3 时不转码。 |
| M4A / MP4 | `m4a`、`m4a-alac`、`mp4`、`mp4-alac` | 默认使用无损 ALAC。 |
| M4A / MP4 | `m4a-aac`、`mp4-aac` | 使用 AAC，码率为 192 kbit/s。 |
| M4A / MP4 | `m4a-mp3`、`mp4-mp3` | 使用 MP3 编码。 |

M4A 和 MP4 始终需要转码；实际转码时需要本机 `ffmpeg` 并确保它在 `PATH` 中。保留原格式不需要 `ffmpeg`。

### 输入与输出

| 参数 | 说明 |
| --- | --- |
| `[输入文件或目录]` | 一个 `.ncm` 文件或目录；默认扫描当前工作目录。格式名与路径重名时，可用 `./mp3` 这类写法明确表示路径。 |
| `[输出目录或文件]` | 不指定时使用 `output/`。现有目录或无扩展名的路径视为目录；带扩展名的路径视为完整文件名，扩展名必须匹配输出格式，且只能用于单个输入文件。 |

### 常用选项

| 参数 | 说明 |
| --- | --- |
| `-r, --recursive` | 递归扫描输入目录；默认只扫描目录当前层。 |
| `-l, --lyrics` | 处理歌词；本地同名 `.lrc` 可选择使用、联网或跳过，没有本地歌词时按有效歌曲 ID 联网查询。 |
| `-f, --force` | 直接覆盖已存在的音频文件，不覆盖已有 `.lrc`。 |
| `-h, --help` | 显示命令帮助。 |
| `-V, --version` | 显示版本。 |

## 输出规则

输出到目录时，文件名优先使用“艺术家 - 歌曲名”；缺少歌曲名时，以输入文件名（不含扩展名）代替歌曲名，因此元数据有艺术家时仍会保留艺术家前缀。文件名中的不安全字符会被替换。指定完整输出文件路径时则使用指定名称并自动创建父目录。

目标音频已存在时，交互终端会询问如何处理。回车或 `y` 覆盖音频。启用 `-l` 时，`n` 保留音频并继续获取这首歌的歌词，Esc 跳过当前项。未启用 `-l` 时，`n` 和 Esc 是同一选项：保留音频并跳过当前项。使用 `-f` / `--force` 会直接覆盖音频，不询问；非交互运行又未指定 `-f` 时不会自动选择，当前项会报错。目录配合 `-r` 时逐首应用同一规则；只找到一首歌时照常处理一次，随后命令结束。

启用 `-l` / `--lyrics` 后，已有的输出同名 `.lrc` 会保留。若 `.ncm` 源文件旁有可读取的非空同名 `.lrc`，程序会询问：回车或 `y` 使用本地歌词，`n` 忽略本地歌词并尝试联网，Esc 跳过歌词。没有本地歌词时，只有 NCM 元数据含有效歌曲 ID 才会联网查询。歌词保存在输出音频旁，始终不覆盖已有 `.lrc`。需要选择但标准输入不是交互终端时，会报告歌词处理失败；已经生成的音频不会撤销。

批量处理时，单个文件出错不会阻止其余文件继续处理；处理结束后，只要有文件失败，程序就会以失败状态退出并报告失败数量。

## 构建与依赖

### 一键构建

在仓库根目录运行：

```sh
sh ./setup.sh
```

脚本会检查 Rustup；若尚未安装，会通过官方安装器安装 Rustup，但不会修改 Rustup 的全局默认版本。随后脚本按仓库的 `rust-toolchain.toml` 获取 stable，运行 `cargo build --release`，并通过临时文件将编译好的二进制替换为根目录的 `ncm-audio`。若直接运行 `cargo build --release`，二进制只会生成在 `target/release/ncm-audio`。

构建需要 `curl` 和网络连接，Cargo 也需要联网下载依赖。脚本适用于 Linux、macOS、WSL 等提供 POSIX `sh` 的环境，不会安装 `ffmpeg`。程序运行时不调用 Cargo；可将二进制移至其他兼容环境使用。若脚本刚安装了 Rustup，要在当前终端使用 `cargo`，运行 `. "$HOME/.cargo/env"` 或重新打开终端。

### 手动安装 Rustup

交互式安装：

```sh
curl https://sh.rustup.rs | sh
```

启用 HTTPS 限制和下载失败检查的非交互安装：

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --default-toolchain stable
```

这两种方式都会将 stable 设为 Rustup 的用户级默认工具链。只想为本项目配置工具链并保留现有默认版本时，使用 `sh ./setup.sh`。

项目内的 `rust-toolchain.toml` 会自动选择 Rust stable 并包含 `rustfmt`。转码时需要本机 `ffmpeg` 并确保它在 `PATH` 中：M4A/MP4 始终转码；FLAC/MP3 只有在输入格式与目标格式不同时才转码；保留原格式不需要 FFmpeg。启用 `-l` 后，找不到本地歌词或选择联网查询时需要网络。

项目通过 Cargo 从源码构建，目前没有独立安装程序或发布二进制包。

## 测试

在项目根目录运行主程序测试：

```sh
cargo test
```

歌词库是独立的 Cargo package，单独运行其测试：

```sh
cargo test --manifest-path lyrics-fetcher/Cargo.toml
```
